要討論A 重工：又「審核」又「寫報告」
A 已經要審核是否 100% 完成（＝審核者），卻又要自己撰寫本週報告（＝報告最終者）。兩個角色疊在同一人身上 → 重工；也造成更新紀錄有兩個來源（R 主管審過的 R 報告 ＋ A 自己寫的報告，圖中紅線）。
核心問題：A 到底是「審核者」，還是「報告最終者」？
• 若 A 只當審核者 → 報告直接用「R 主管審核通過的 R 報告」，A 不用再自己寫（可拿掉 A 撰寫台，更新紀錄也只剩一個來源）。
• 若 A 是報告最終者 → 那「R 主管審核」是在審什麼？會不會同一份東西審兩次？
？ 尚未回覆 —— 進度百分比以誰為主：依 A 報告日還是 R 報告日推算 %（見議題 2）。這題沒答，進度與甘特無法定案。
✓ 已確認沒問題：R 主管由 A 指派、A 送出延期申請 → S 審核、採用新流程（R 主管 → 大 A）。這幾塊維持即可，不用討論。

目前系統角色只有 R / A / S / C / I / P，沒有「R 主管」這個獨立審核角色。

2更新紀錄與進度的「來源」改變（影響最大）

現有：更新紀錄／進度／甘特一律以「A 送出的報告」為準（即剛完成的「A 為主 + 7/12 相容」整套邏輯）。
示意 · 更新紀錄的內容從哪來？
現況 R 紀錄→原料 A 報告→ 更新紀錄來源＝A
新版 R 紀錄→主管✓ 更新紀錄來源＝R
示意 · 進度 % 依「誰的報告日」推算（同一任務可能不同）
進度 = 報告日落在計畫期間的位置。例：計畫 10/1～10/20，報告日越後面、% 越高。
現況 · 依 A 報告日 10/12
60%
新版 · 依 R 報告日 10/9
45%
同一個任務，用 A 或 R 的報告日，算出的 % 不一樣 → 要決定進度以誰的日期為準。
示意 · 父層／子層進度（現在「各自為準」）
目前父任務、子任務的 % 各自獨立輸入，父的數字不等於子層的平均。

來源從 A 變成 R，牽動兩件事：
• 進度日期：進度、甘特實際條依誰的報告日推算 %（A 還是 R）？
• 父子聚合：父層／子層進度目前各自為準，新版要不要改成「父＝子層聚合」、里程碑以誰為準？
若改以 R 為主，先前「A 為主」共用於 8 處的濾鏡與 7/12 相容處理需重做／調整。

牽動：進度計算、甘特、更新紀錄、概覽週彙整、父子/里程碑聚合（剛做完的相容邏輯可能重做）。

3大 A 的角色：從「撰寫」變「審核完成度」

現有：A 要匯入 R 紀錄、彙整成報告並送出。新版：A 不寫報告，只「審核是否 100% 完成」。
示意 · 大 A 做的事變了
現況 · A ✍ 撰寫者
  • 匯入 R 紀錄
  • 彙整成一份報告
  • 撰寫內容、送出
新版 · A ✔ 審核者
  • 不寫報告
  • 只審「是否 100% 完成」
  • Pass / Fail
需要決定：「A 撰寫本週報告」功能還保留嗎？A 審核單位是單一任務還是里程碑？「是否 100%」是 A 主觀判定還是看系統算出的進度？
□ 保留 A 撰寫台 □ 廢除 A 撰寫台 □ A 審單一任務 □ A 審里程碑

4兩段審核 = 兩個等待點（卡控與逾時）

新版多了兩個可能「卡住」的點：R 主管沒審、大 A 沒審。
示意 · 多了兩個「等審核」的卡點
R 填完 ⏳等主管 主管 ✓ ⏳等大 A 大 A ✓ → 完成
需要決定：審核有沒有時限？逾時要提醒／自動放行／往上升級？（同先前 S 延期審核未審的卡點問題）
□ 無時限 □ 逾時提醒 □ 逾時自動放行

現有整套是「週」制：A 每週彙整送一次（weekOf）。新版流程是「逐任務」跑審核鏈，看不到「週」。
