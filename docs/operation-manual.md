## 版本 2.0 更新摘要

本版導入客戶確認的新報告流程與相關調整，重點如下（詳細操作見對應章節，流程圖見 `flow-v02.html`）：

1. **報告審核主管（R主管）流程**：執行者（R）填的工作紀錄，先由其「R主管」審核（通過／駁回），核准才進更新紀錄並推動進度；未設 R主管者回退由當責 A 審。（見 §6、§8）
2. **進度來源改依指派人**：有指派人的任務以該 R 的報告推算進度；無指派人的葉任務以 A 的報告；無指派人的父任務由子層加權聚合。A 對「有指派人」任務所寫的是**補充**，不影響進度。（見 §8）
3. **A 撰寫台改「補充」概念＋查看子層報告**：撰寫台分「看 R 報告／我的補充（或我的報告）」；被指派到父任務的 R 可查看子任務過往週報作參考。（見 §8）
4. **完成確認**：A 在審核中心「審核通過」＝確認任務 100% 完成（設 100%、進完成區、里程碑同步）；須先過 R主管核准 A 才看得到。（見 §6、§8）
5. **延期改由 A 判斷**：報告或完成日可超過計畫截止日、不再強制跳延期；A 認為需改計畫時程時才提延期。（見 §7）
6. **里程碑階段總覽（專案概覽）**：專案頁新增階段時間軸總覽，含「顯示設定」（分開／合併、貼合／展開時間軸、顯示階段）。（見 §5.3）
7. **通知強化**：新增待審核報告／報告已進更新紀錄／待審核完成／審核逾期；側邊欄收合仍可見未讀數，通知中心可搜尋與依類型篩選。（見 §9）

## 1. 系統簡介

本系統為企業級專案管理平台，提供以下核心功能：

- **專案生命週期管理** — 從建立、追蹤到完結
- **里程碑與任務管理** — 階層式任務、依賴追蹤、進度自動同步
- **RACIPS 團隊角色** — 六種專案角色（負責/當責/諮詢/知會/採購/簽核）
- **延遲申請審批** — 多人審核機制，自動更新里程碑日期
- **週報機制** — PM 週報、成員週報、自動提醒
- **通知系統** — 站內通知 + Email 通知
- **預算與 CAPEX 管理** — 設備採購追蹤、付款進度
- **風險管理** — 風險登記、影響評估、緩解追蹤
- **執行儀表板** — KPI 統計、狀態總覽
- **報表匯出** — PDF / Excel / Email 分發

### 系統角色

| 角色 | 代碼 | 說明 |
|------|------|------|
| 系統管理員 | admin | 最高權限，可管理使用者、系統設定、所有專案 |
| 專案經理 | pm | 建立/編輯/刪除專案，管理團隊與預算 |
| 高階主管 | executive | 檢視所有專案、審批延遲、處理支援需求 |
| 團隊成員 | member | 參與指派的專案、更新任務狀態、撰寫日誌 |

## 2. 環境需求與安裝

### 2.1 系統需求

| 項目 | 需求 |
|------|------|
| 作業系統 | Windows / macOS / Linux |
| Node.js | 18.0+ |
| 資料庫 | MySQL 8.0+ 或 MariaDB 10.6+ |
| 記憶體 | 建議 2GB+ |
| 硬碟 | 建議 10GB+ |
| 瀏覽器 | Chrome / Edge / Firefox 最新版本 |

### 2.2 安裝步驟

```bash
# 1. 取得程式碼
git clone <repository-url>
cd project-management-system

# 2. 安裝套件
npm install

# 3. 設定環境變數
# 複製 .env.example 為 .env 並填寫以下設定：
#   DATABASE_URL=mysql://user:pass@host:33306/dbname
#   AD_URL=https://apigw.company.com   (AD 認證 API 位址)
#   AD_API=your_api_key                 (AD API 金鑰)
#   APP_URL=http://localhost:12039       (應用程式 URL)
#   CRON_SECRET=your_cron_secret         (排程任務密鑰)

# 4. 啟動資料庫 (Docker)
docker-compose up -d

# 5. 推送資料庫 Schema
npx prisma db push

# 6. 載入初始資料
npx prisma db seed

# 7. 啟動系統
npm run dev    # 開發模式
npm run build && npm run start  # 正式環境
```

## 3. 登入系統

### 3.1 登入頁面

開啟瀏覽器前往系統網址（預設為 `http://localhost:12039`），系統會自動導向登入頁面。

**登入頁面包含：**

- **系統標題：** 「專案管理系統 — AI 驅動的智慧專案管理平台」
- **歡迎文字：** 「歡迎回來，請登入您的帳號以繼續」

### 3.2 帳號密碼登入

1. 在 **帳號** 欄位輸入您的 AD 工號或電子郵件
2. 在 **密碼** 欄位輸入密碼
3. 點擊 **「登入」** 按鈕

> **認證順序：** 系統會先嘗試 AD（Active Directory）認證，若 AD 不可用，則使用內建帳號認證。

### 3.3 快速登入（測試/展示用）

登入頁面下方「快速登入」區域提供四張角色卡片，點擊即可一鍵登入：

| 卡片 | 角色 | 帳號 |
|------|------|------|
| **A** - 系統管理員 | Admin | alice@example.com |
| **D** - 專案經理 | PM | dave@example.com |
| **B** - 團隊成員 | Member | bob@example.com |
| **C** - 高階主管 | Executive | carol@example.com |

### 3.4 登出

1. 點擊右上角的使用者頭像或名稱
2. 在下拉選單中點擊 **「登出」**
3. 系統清除登入狀態並導回登入頁面

## 4. 儀表板操作

登入後自動進入儀表板頁面（`/dashboard`）。

### 4.1 頁面結構

頁面頂部顯示：
- **「儀表板」** 標題
- **「歡迎回來，[您的名稱]」** 問候語

### 4.2 篩選工具列

位於頁面頂部的篩選工具列提供以下功能：

**日期範圍篩選：**
- 點擊日期範圍按鈕，可選擇預設範圍：
  - **今年** / **去年** / **近 3 個月** / **近 6 個月**
- 或自訂 **開始日期** 和 **結束日期**

**層級篩選（按鈕群組）：**
- **全部** — 顯示所有層級
- **T1** / **T2** / **T3** / **CIP** — 僅顯示特定層級

**其他按鈕：**
- **重設** — 清除所有篩選條件
- **[N] 筆待審核** — 顯示待審核數量（點擊跳轉至審核中心）

### 4.3 統計卡片

儀表板顯示以下統計卡片（依角色不同略有差異）：

| 卡片名稱 | PM/Admin/Executive | Member |
|---------|-------------------|--------|
| 第一張 | **總專案數** | **參與專案** |
| 第二張 | **專案層級** (T1/T2/T3/CIP 各數量) | 同左 |
| 第三張 | **預算使用率** | **我的任務** (含已完成數) |
| 第四張 | **健康度** (正常/總數比) | 同左 |

### 4.4 資訊面板

統計卡片下方有四個資訊面板：

1. **專案總覽**（PM/Admin/Executive）或 **我的專案**（Member）
   - 列出專案卡片，包含名稱、狀態燈號（**正常**/​**注意**/​**風險**）、進度條
   - 顯示 「共 [N] 筆」

2. **風險摘要**
   - 列出所有開放風險
   - 顯示 「共 [N] 項」
   - 空狀態顯示：「目前無風險」

3. **即將到期的里程碑**
   - 列出未來 7 天內到期的里程碑
   - 顯示 「共 [N] 項」
   - 空狀態顯示：「近期無到期里程碑」

4. **本週末更新**
   - 列出本週缺少更新的專案
   - 空狀態顯示：「所有專案皆已更新」

### 4.5 說明按鈕

點擊頁面右上角的說明圖示，可開啟 **「儀表板說明」** 對話框，了解各統計指標的定義。

## 5. 專案管理

### 5.1 瀏覽與搜尋專案

**路徑：** 側邊欄 → **「專案看板」**

進入專案看板頁面（`/projects`）：

**頁面標題：** 「專案看板 — 管理和追蹤所有專案的進度與狀態」

**篩選工具列：**

| 篩選項目 | 操作方式 |
|---------|---------|
| 關鍵字搜尋 | 輸入框「搜尋專案名稱、目標或編碼...」 |
| 層級篩選 | 下拉選單：**全部層級** / T1 / T2 / T3 / CIP |
| 類型篩選 | 下拉選單：**全部類型** / NPI / 成本優化 / 品質改善 / 自動化 / ... |
| 狀態篩選 | 下拉選單：**全部狀態** / **正常** / **注意** / **風險** |
| 更多篩選 | 點擊 **「更多篩選」** 按鈕展開進階篩選 |
| 重設 | 點擊 **「重設」** 清除所有條件 |

**進階篩選（更多篩選）：**
- **負責人** — 下拉選單「全部負責人」
- **需求者** — 下拉選單「全部需求者」
- **日期範圍** — 預設（今年/去年/近3個月/近6個月）或自訂

**專案卡片資訊：**
- 狀態燈號：**正常**（綠）/ **注意**（黃）/ **風險**（紅）
- 專案代碼與名稱
- 進度條與百分比
- 底部資訊：[N] 人、日期、預算（$[M]M/$[B]M）、Owner · [done]/[total] 里程碑

**分頁：**
- 每頁 12 個專案
- 底部顯示「共 [N] 個專案，第 [X]/[Y] 頁」

**無搜尋結果：** 「找不到符合條件的專案」

**權限說明按鈕：** 點擊頁面右上角圖示，可開啟 **「專案看板 — 權限說明」**

### 5.2 建立新專案

**路徑：** 專案看板 → **「建立新專案」** 按鈕

> **權限：** 僅 PM 和 Admin 角色可建立專案。

系統提供兩種建立模式：

- **手動模式** — 逐步填寫表單
- **AI 模式** — 上傳需求文件，AI 協助解析

#### 手動模式步驟精靈：

**第 1 步：基本資訊**

| 欄位 | 說明 | 必填 |
|------|------|------|
| 專案名稱 | 輸入專案名稱 | ✅ |
| 專案類型 | 選擇類型（NPI / 成本優化 / 品質改善 / 自動化 / ...） | ✅ |
| 專案層級 | 選擇 T1 / T2 / T3 / CIP | ✅ |
| 需求來源 | 公司政策 / 外部需求 / 內部需求 / 自提 | ✅ |
| 負責人 | 搜尋 AD 使用者選擇 | ✅ |
| 起始日期 | 日期選擇器 | ✅ |
| 結束日期 | 日期選擇器 | ✅ |
| 預算 | 輸入數字 | ✅ |

**第 2 步：SMART 目標**

| 欄位 | 說明 |
|------|------|
| Specific（具體目標） | 文字輸入 |
| Measurable（可衡量指標） | 文字輸入 |
| Achievable（可達成性） | 文字輸入 |
| Relevant（相關性） | 文字輸入 |
| Time-bound（時限） | 文字輸入 |

**第 3 步：專案定義**

| 欄位 | 說明 |
|------|------|
| 目標（Objective） | 文字輸入 |
| 目的（Purpose） | 文字輸入 |
| 範圍（Scope） | 文字輸入 |
| ROI | 文字輸入 |
| 預期效益 | 文字輸入 |
| ROI 指標 | 毛利率 / 平均價格 / 產能 等數值 |

**第 4 步：團隊與風險**

*團隊成員：*
- 搜尋 AD 使用者名稱
- 為每位成員指定 RACIPS 角色：
  - **R** — 負責執行
  - **A** — 當責
  - **C** — 諮詢
  - **I** — 知會
  - **P** — 採購
  - **S** — 簽核（審核延遲申請的權限）
- 填寫職稱、組織、職責說明

*風險登記：*
- 風險標題（例如：「供應商交期不穩定」）
- 影響程度：**影響低** / **影響中** / **影響高**
- 發生機率：**機率低** / **機率中** / **機率高**
- 風險描述（選填）
- 緩解對策（選填）

**第 5 步：時程里程碑**

- 選擇專案類型後，系統自動載入對應的里程碑模板
- 可手動新增/刪除/調整里程碑
- 為每個里程碑新增任務
- 設定任務間的依賴關係

點擊 **「建立專案」** 完成建立，系統自動產生專案代碼（如 `NPI-2026-001`）。

### 5.3 檢視專案詳情

**路徑：** 專案看板 → 點擊專案卡片

專案詳情頁包含以下九個分頁：

| 分頁 | 功能說明 |
|------|---------|
| **時間軸** | 里程碑與任務的甘特圖時間軸 |
| **任務** | 任務看板（待辦/進行中/完成/阻塞） |
| **里程碑** | 各里程碑進度追蹤 |
| **團隊** | 團隊成員列表與 RACIPS 角色 |
| **預算** | 預算項目清單（站別、廠商、設備、費用） |
| **風險** | 風險登記與狀態追蹤 |
| **延遲** | 延遲申請歷史紀錄 |
| **更新** | 週報更新紀錄 |
| **CAPEX** | 資本設備追蹤（PO、付款進度） |

**頂部統計：**
- 整體進度百分比
- 狀態燈號（正常/注意/風險）
- 預算使用率

**里程碑階段總覽（專案概覽，v2.0）：** 於「工作項目」分頁上方，以里程碑為「階段」呈現時間軸總覽：階段條（依狀態上色）＋年月軸＋Plan／Actual 兩列；Actual 依已發布報告的最後日期繪製。可收合。

- **顯示設定**（限該專案的 A／pm／admin 調整，其他人套用）：
  - **重疊階段**：分開（自動分層、互不遮擋）／合併（擠成一列）。
  - **時間軸寬度**：貼合（全部縮入畫面，適合短專案）／展開時間軸（固定月寬、顯示月份、可橫向捲動，適合長專案）。
  - **顯示階段**：勾選要顯示哪些里程碑。

### 5.4 編輯專案

### 5.5 刪除專案

**路徑：** 專案詳情 或 專案列表 → **「刪除」** 按鈕

> **權限：** 僅 PM 和 Admin 可刪除。

1. 點擊刪除按鈕
2. 系統彈出確認對話框
3. 確認後，專案及所有相關資料（里程碑、任務、風險、通知等）一併刪除

⚠️ **刪除操作不可恢復，請謹慎操作。**

---

### 5.6 共享專案

**路徑：** 專案詳情 → **「共享」** 按鈕

1. 點擊共享按鈕
2. 可設定到期日（選填）
3. 系統產生唯一的共享連結
4. 將連結複製給需要檢視專案的人員
5. 收到連結的人員無需登入即可檢視專案唯讀資訊

> 共享連結到期後將自動失效，存取時顯示「連結已失效」。

## 6. 我的任務

### 6.1 任務總覽

**路徑：** 側邊欄 → **「我的任務」**

本頁面顯示所有指派給您的任務，依您在各專案中的 RACIPS 角色分類。

### 6.2 任務角色分頁

頁面頂部依 RACIPS 角色顯示分頁標籤：

| 分頁 | 角色 | 說明 |
|------|------|------|
| **審核** | S（簽核） | 審核延期申請 |
| **當責** | A（當責） | 填寫週報、管理任務 |
| **採購** | P（採購） | 管理採購資訊 |
| **執行** | R（負責） | 填寫工作週報 |
| **諮詢** | C（諮詢） | 查看專案進度 |
| **知會** | I（知會） | 查看專案進度 |

> 僅顯示您有被指派的角色分頁。例如您在某專案擔任 R 和 A 角色，就會看到「執行」和「當責」兩個分頁。

### 6.3 任務狀態說明

每個任務會自動計算顯示狀態：

| 狀態 | 顯示文字 | 顏色 | 條件 |
|------|---------|------|------|
| 完成 | **已完成** | 綠色 | 任務已標記完成 |
| 正常進行 | **準時進行中** | 藍色 | 進行中且未逾期 |
| 有風險 | **有風險** | 黃色 | 進行中但接近逾期 |
| 逾期 | **逾期** | 紅色 | 超過截止日仍未完成 |
| 逾期未開始 | **逾期未開始** | 紅色 | 超過開始日仍為待辦 |
| 未開始 | **尚未開始** | 灰色 | 待辦狀態 |

### 6.4 更新任務狀態

**操作步驟：**

1. 在我的任務頁面找到目標任務
2. 點擊任務卡片展開詳情
3. 可執行以下操作：
   - **標記完成** — 將任務設為已完成，記錄完成時間
   - **恢復** — 將已完成的任務恢復為進行中
   - **更新進度** — 手動調整進度百分比

> **自動狀態更新：** 系統會根據以下條件自動推進任務狀態：
> - 任務開始日期已過 → 自動從「待辦」變為「進行中」
> - 前置任務未完成 → 自動設為「阻塞」
> - 有工作日誌但狀態仍為待辦 → 自動設為「進行中」

### 6.5 撰寫工作日誌（工作紀錄）

**操作步驟：**

1. 於「我的任務 › 填寫週報」選擇填報週別
2. 展開任務，填寫工作紀錄：
   - **日期** — 工作日期（可多筆、不限當週）
   - **工作內容** — 該日完成的工作
   - **附件** — 上傳圖片或文件（選填）
   - **預計下週工作** — 下一步計畫（選填）
3. 點擊 **提交週報**

> **送出卡控（v2.0）：** 每一列都要同時填「日期」與「工作內容」、且內容有變更才能送出；空白或未變更的列會擋下並提示。

> **報告流向（v2.0）：** 送出後系統依你是否設有「報告審核主管（R主管）」路由：有 R主管 → 送 R主管審核（送出後 Toast 會顯示送交對象）；未設 → 回退送當責 A。**未經核准前，你的紀錄不影響官方進度與甘特圖。** 重送「已通過」的報告會讓該「任務×填報週」整週回到待審核（需先確認）。

**查看子層報告（v2.0）：** 若你被指派到「有子任務的父任務」，展開區內會多出「撰寫報告／查看子層報告」分頁。切到「查看子層報告」可用下拉挑任一子任務，唯讀檢視其過往每週報告，作為你撰寫父層報告的參考。

### 6.6 我是 R主管：審查報告（v2.0）

若你被指定為某些成員的「報告審核主管（R主管）」，於「我的任務 › 審查報告」審核他們的報告。對話框含三分頁：

- **待審核** — 尚未審的報告，可展開看報告表格（日期／工作內容／附件；附件以圖示＋數量呈現、hover 可下載）。可 **通過** 或 **駁回（填原因）**；不可修改或代送報告。
- **已審核** — 已通過／已駁回的報告紀錄。
- **填報追蹤** — 依填報週檢視誰未如期填報；逾期未完成者持續每週追蹤到任務完成。

> 通過 → 報告進更新紀錄、推動進度，並通知 A；駁回 → 退回該 R 的「待完成」並附原因。

### 6.7 子任務管理

若任務有子任務，可在任務詳情中管理：

1. 點擊 **「新增子任務」**
2. 填寫子任務標題、負責人、截止日
3. 子任務的完成比例會自動計算父任務的進度（父任務無指派人時，進度＝子層加權聚合）

## 7. 延遲申請與審核

### 7.1 提交延遲申請

**路徑：** 專案詳情 → **延遲** 分頁 → **「提交延遲申請」**（A 撰寫台亦有常駐入口）

> **權限：** 由當責 A 判斷提出（PM／admin 亦可）。

> **延期新定義（v2.0）：** 報告或實際完成日**可以超過**計畫截止日，系統**不再強制**、也不會跳出強制申請視窗。只有當 A 認為專案確實需要**調整計畫時程**時，才主動提出延期申請。

**填寫內容：**

| 欄位 | 說明 | 必填 |
|------|------|------|
| 延遲類型 | **延期申請** 或 **日期異動** | ✅ |
| 延遲原因 | 詳細描述延遲原因 | ✅ |
| 能否追回 | 是 / 否 | ✅ |
| 是否需要支援 | 勾選並說明所需支援（如：「需要加急供應商交貨」） | 選填 |
| 受影響里程碑 | 選擇受影響的里程碑，填寫原定日期和建議新日期 | ✅ |

**提交後：**
- 系統自動計算需要審核的 S 角色（簽核）成員數量
- 所有 S 角色成員收到 **「延遲申請已提交」** 通知
- 若標記需要支援，主管會收到 **「支援需求」** 通知

---

### 7.2 審核延遲申請

**路徑：** 側邊欄 → **「審核中心」**

> **權限：** 僅專案中 S（簽核）角色的成員可審核。

審核中心分為三個分頁：

#### **待審核** 分頁

1. 列出所有等待您審核的延遲申請
2. 每個申請顯示：
   - 專案名稱與代碼
   - 申請人與申請日期
   - 延遲原因
   - 受影響里程碑（原定日期 → 建議新日期）
   - 能否追回、是否需要支援
   - 已有多少審核者已通過

3. 審核操作：
   - 點擊 **「核准」** → 填寫審核備註 → **「提交」**
   - 點擊 **「駁回」** → 填寫駁回理由 → **「提交」**

**審核規則：**
- ✅ **全數核准** — 所有 S 角色成員都核准後，申請狀態變為「已核准」
- ❌ **任一駁回** — 只要有一位駁回，申請立即變為「已駁回」
- 核准後，受影響里程碑的日期自動更新為建議新日期

**篩選工具：**
- 搜尋關鍵字
- **更多篩選** — 可依層級、專案類型、申請人、負責人、申請日期篩選
- **清除篩選** — 重設所有條件

**類型篩選：**
- **全部類型** / **延期申請** / **日期異動**

---

### 7.3 支援需求處理

**路徑：** 審核中心 → **「待協助」** 分頁

> **權限：** Admin 和 Executive 角色可處理。

1. 檢視需要支援的延遲申請
2. 了解支援需求內容
3. 在 **「協助備註」** 中填寫處理內容
4. 點擊 **「標記已協助」** 完成處理

---

### 7.4 審核紀錄

**路徑：** 審核中心 → **「審核紀錄」** 分頁

- 檢視所有已核准和已駁回的歷史紀錄
- 篩選：**全部結果** / **已核准** / **已駁回**

## 8. 週報與進度追蹤

### 8.1 PM 週報

**路徑：** 專案詳情 → **更新** 分頁 → **「新增週報」**

PM 每週需提交專案進度報告，包含：

| 欄位 | 說明 |
|------|------|
| 週次 | 選擇本週一的日期 |
| 整體狀態 | **準時** 或 **延遲** |
| 各里程碑進度 | 針對每個里程碑更新進度百分比與備註 |
| 阻礙事項 | 描述本週遇到的問題 |
| 關鍵成就 | 本週重要完成事項 |
| 下週計畫 | 下週工作重點 |

### 8.2 執行者（R）工作紀錄

團隊成員（R）於「我的任務 › 填寫週報」填寫被指派任務的工作紀錄（日期＋內容＋附件）。詳細操作與送出卡控、報告流向、查看子層報告見 **§6.5**。

> 送出後依是否設有 R主管路由審核；未經核准前不影響官方進度。

### 8.3 A 撰寫台（補充概念，v2.0）

**路徑：** 專案詳情 → 撰寫本週報告（當責 A）

撰寫台頁層分「**本週彙整** ｜ **填任務報告**」；每個任務內再分「**看 R 報告** ｜ **我的補充／我的報告**」。呈現與是否驅動進度依任務指派狀態不同：

| 任務型態 | 看到什麼 | A 要填什麼 | 誰驅動進度 |
|---|---|---|---|
| 有指派人 | R 報告（唯讀） | 我的**補充**（提供脈絡） | R 的報告 |
| 無指派人・葉任務 | — | 我的**報告**（可標記完成） | A 的報告 |
| 無指派人・父任務 | 子層聚合說明 | 不需填 | 子層加權聚合 |

> 任務清單會標示哪些「有押人／未押人」，待 A 填報的無押人任務以琥珀色標示。**送出**才發布於更新紀錄、更新進度、套用標記完成；**暫存**僅保存內容。

### 8.4 進度計算方式（依指派人，v2.0）

- **有指派人**：以該指派人（R，經 R主管核准後）的報告日期推算；A 的補充不影響。
- **無指派人・葉任務**：以 A 的報告日期推算。
- **無指派人・父任務**：由子任務依天數加權聚合。
- 一律自動最高 99%；標記完成／A 確認完成才 100%。里程碑進度＝其下計入任務加權平均（排除無指派人的純聚合父任務）。

### 8.5 完成確認（A，v2.0）

任務回報 100% 完成後，由 A 於「審核中心」確認：

1. **前置**：若該任務指派人設有 R主管，完成報告須先經 R主管核准，A 才會在待確認看到（未設則直接進 A）。
2. **審核通過 ＝ 確認 100% 完成**：設 100%、記錄完成日與完成人，反映於甘特（完成）、完成區與里程碑。
3. **駁回**：填原因、退回 R 的「待完成」。

> **自動提醒：** 系統會在設定的時間自動檢查未提交週報的專案，並發送通知與 Email 提醒。

## 14. 常見問題（FAQ）

### Q1：忘記密碼怎麼辦？
**A：** 測試帳號密碼統一為 `demo`。正式環境中密碼由 AD（Active Directory）管理，請聯繫 IT 部門重設密碼。

### Q2：為什麼看不到「管理後台」選項？
**A：** 管理後台僅限 Admin 角色存取。如需管理員權限，請聯繫系統管理員為您指派 `admin` 角色。

### Q3：任務狀態為什麼自動變更了？
**A：** 系統有自動狀態同步機制：
- 開始日期已過 → 自動從「待辦」變為「進行中」
- 前置任務未完成 → 自動設為「阻塞」
- 有工作日誌但仍為待辦 → 自動設為「進行中」

### Q4：延遲申請需要多少人審核？
**A：** 需要專案中所有 S（簽核）角色成員全數核准。任何一位駁回即立刻駁回整個申請。

### Q5：里程碑進度是怎麼計算的？
**A：** 里程碑進度 = 各任務進度的加權平均，權重為任務的天數（durationDays）。
公式：`Σ(task.progress × task.durationDays) / Σ(task.durationDays)`

### Q6：專案狀態燈號的判定標準是什麼？
**A：**
- **🟢 正常（Green）** — 所有任務按時進行
- **🟡 注意（Yellow）** — 有少量逾期或阻塞（逾期 < 30%，阻塞 < 20%）
- **🔴 風險（Red）** — 逾期 ≥ 30% 或阻塞 ≥ 20% 或已超過結束日仍未完成

### Q7：通知多久更新一次？
**A：** 系統每 20 秒自動輪詢一次新通知。首次載入頁面時也會立即抓取。

### Q8：如何自訂週報提醒的排程？
**A：** 系統管理員可在「管理後台 → 通知設定」中，為各專案層級（T1/T2/T3/CIP）分別設定提醒頻率、星期幾和時間。

### Q9：共享連結會不會有安全疑慮？
**A：** 共享連結僅提供唯讀檢視，無法編輯或刪除。可設定到期日，過期後自動失效。

### Q10：`prisma migrate dev` 為什麼失敗？
**A：** 遠端資料庫不允許建立 shadow database。請改用 `npx prisma db push` 推送 schema 變更。

### Q11：如何備份/還原資料庫？
**A：**
```bash
# 備份
mysqldump -h host -u user -p db_name > backup.sql

# 還原
mysql -h host -u user -p db_name < backup.sql
```

### Q12：Cron 排程不執行怎麼辦？
**A：** 檢查以下項目：
1. 確認排程已在「管理後台 → 排程管理」中啟用
2. 確認當前時間與設定的星期/小時相符
3. 檢查 CronJobLog 中的執行紀錄是否有錯誤
4. 可使用「手動執行」按鈕測試
