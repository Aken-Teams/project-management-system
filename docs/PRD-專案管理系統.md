## 1. 產品概述

### 1.1 目的
提供以「里程碑—任務」為核心的專案管理平台，讓團隊依角色分工，透過每週報告更新進度、以延期審核控管時程，並以通知維持協作。

### 1.2 目標使用者
專案經理（PM）、當責者（A）、執行者（R）、審核者（S）、採購（P）、主管與一般成員。

### 1.3 核心設計原則
1. **進度來源依指派人**：有指派人的任務以該指派人（R）的報告驅動進度；無指派人的葉任務以 A 的報告驅動；無指派人的父任務由子層加權聚合。
2. **報告經審核才入帳**：R 的工作紀錄須經其「報告審核主管（R主管）」核准，才發布於更新紀錄並驅動進度；未設 R主管者回退由 A 為準。
3. **完成以 A 為準**：任務 100% 完成（標記完成／確認 R 回報完成）一律由 A 拍板，反映於甘特、完成區與里程碑。
4. **手動為主**：日常時程以團隊手動調整為準，不自動連動。
5. **延期由 A 判斷、核准才連動**：報告日期可超過計畫截止日而不強制送延期；是否調整計畫時程由 A 判斷提出，經 S 核准後才連動群組與下游。

## 2. 名詞定義

| 名詞 | 定義 |
|---|---|
| 里程碑 | 專案的階段性節點，底下掛任務。 |
| 任務 / 子任務 | 工作項目，可多層巢狀（里程碑＋最多 5 層任務，共 6 層）。 |
| 工作紀錄 | R 每週填寫的工作內容（日期＋內容＋附件）。 |
| 報告審核主管（R主管） | 於團隊設定中為某成員指定的報告審核人；審核該成員（R）的工作紀錄（通過／駁回），不代寫、不代送。未設定則回退由 A 審。 |
| 週報 / 正式報告 | A 彙整後送出的報告，作為官方依據。 |
| 補充報告 | A 對「有指派人」任務所寫的補充說明，提供脈絡但**不驅動**該任務進度。 |
| 查看子層報告 | 被指派到父任務的 R，可唯讀檢視其子任務過往每週報告，作為撰寫參考。 |
| 里程碑階段總覽（專案概覽） | 專案頁上以里程碑為「階段」的時間軸總覽（階段條、年月軸、Plan／Actual 兩列）。 |
| 填報週（weekOf） | 報告所屬的週別（週一為基準）。 |
| 標記完成 | A 將任務設為完成（100%），需填實際完成日。 |
| 開案 | 專案由「草稿」進入「已開案」，時程定版。 |
| 延期申請 | 調整**計畫時程**的正式申請，由 A 判斷提出、經 S 審核；報告超過截止日本身不強制申請。 |

## 3. 角色與權限

### 3.1 系統角色（登入身分）
| 角色 | 權限範圍 |
|---|---|
| admin 管理員 | 系統設定、使用者與角色、通知與報告排程；最高權限。 |
| pm 專案經理 | 建立與管理專案、指派任務、開案、審核。 |
| executive 主管 | 跨專案儀表板、整體進度與風險。 |
| member 一般成員 | 填寫自身工作紀錄、檢視被指派任務。 |

### 3.2 專案分工角色（每專案指派，RASCI＋P）
| 角色 | 職責 |
|---|---|
| R 負責 | 執行任務、填寫工作紀錄、回報進度、管理子任務。 |
| A 當責 | 撰寫正式週報、審核 R 回報、標記任務完成、提出延期申請。 |
| S 審核 | 審核延期申請（核准／駁回）。 |
| P 採購 | 設備採購與供應商管理、採購項目與資本支出（投資報酬）維護。 |
| C 諮詢 | 決策前被徵詢的專家。 |
| I 知會 | 被告知進度與決策結果，不直接參與執行。 |

> **報告審核主管（R主管）** 非 RASCI 角色，而是「每位成員可各自指定的報告審核人」：於建立／編輯專案的團隊設定中填寫（限 A／pm／admin 編輯）。R 送出報告後由其 R主管審核（通過／駁回）；未指定則回退由 A 審核。R主管只能通過／駁回、不能改報告或代送。

## 4. 功能需求

> 每項標示：**角色**（操作者）、**描述**、**規則**、**驗收標準**。

### 4.1 專案建立與開案

**FR-4.1.1 建立專案（精靈）** — 角色：PM／admin
- 描述：以精靈建立專案，分頁依序為：基本資訊、SMART 目標、專案定義、團隊與風險、時程里程碑。可「AI 快速產生規劃」帶入初稿，或手動輸入；可隨時「儲存草稿／載入草稿」。
- 規則：建立後狀態為「草稿」；被指派者收到「任務指派」通知；指派人僅能從專案成員中選擇。
- 驗收：完成精靈後專案出現於看板（草稿）；被指派者收到通知。

**FR-4.1.2 里程碑與任務結構編輯** — 角色：PM／admin
- 描述：於「時程里程碑」分頁建立里程碑與任務的階層。每列可填：名稱、日曆天、開始／結束日期、指派人、優先度。
- 規則：
  - 新增里程碑、任務、子任務。
  - 縮排／升階：任務可變為上一列的子項，或往上提一層（子任務→任務→里程碑）。
  - 拖曳：調整順序或改變層級（拖曳過程日期保留）。
  - 里程碑降階為相鄰里程碑下的任務。
  - 階層上限 6 層（里程碑＋5 層任務）。
  - 日期以手動輸入為準，不自動連動。
- 驗收：可建立 6 層結構；縮排／升階／拖曳操作正確且日期保留。

**FR-4.1.3 開案** — 角色：PM／admin
- 描述：規劃完成後點「開案」，狀態由「草稿」變「已開案」。
- 規則：開案後，計畫日期調整需經延期審核；系統開始發送逾期與週報催繳通知。草稿階段不催繳、不計逾期。
- 驗收：開案後日期調整觸發延期流程；排程通知僅對已開案專案發送。

### 4.2 每週報告

> **報告流向**：R 填寫工作紀錄 → **R主管審核**（通過＝進更新紀錄／駁回＝退回 R）→ 100% 完成的任務再交 **A 確認**。未設 R主管者，R 報告直接回退由 A 審。

**FR-4.2.1 R 填寫工作紀錄** — 角色：R
- 描述：於「我的任務 › 填寫週報」選填報週別，填寫日期＋工作內容（可附件、多筆），提交。視窗含四分頁：待完成、待確認、完成區、審視歷程。若展開的是「有子任務」的任務，展開區內另有「撰寫報告／查看子層報告」分頁：可用下拉挑任一子孫任務，唯讀檢視其過往每週報告作為撰寫參考。
- 規則：
  - 每列須**同時**填日期與工作內容、且內容有變更才能提交（空白／未變更擋下），提交鈕顯示對應提示。
  - 送出後依該成員是否設定 R主管**路由**：有 R主管 → 送 R主管審核並通知；未設 → 回退送 A。提交後 toast 顯示送交對象。
  - 此為原始紀錄，未經核准前不影響官方進度與甘特圖。
  - 重送「已通過」的報告 → 該「任務×填報週」整週回到待審核（需先確認）。
- 驗收：空白／未變更不能送出；送出後顯示送交對象；有子任務時可查看子層報告；重送已通過報告會整週回審。

**FR-4.2.2 R主管審核報告** — 角色：R主管
- 描述：於「我的任務 › 審查報告」審核所督導成員的報告。對話框含三分頁：**待審核／已審核／填報追蹤**，各列可展開看報告表格（日期／工作內容／附件；附件以圖示＋數量呈現，hover 可下載）。
- 規則：
  - 僅能**通過**或**駁回（填原因）**，不可改報告、不可代送。
  - 通過 → 發布於更新紀錄、驅動進度，並通知 A（該任務已進更新紀錄）。
  - 駁回 → 退回 R 的「待完成」並附原因。
  - 填報追蹤依**填報週**判定誰未如期填；逾期未完成者持續每週追蹤到任務完成。
- 驗收：通過後報告入更新紀錄、A 收到通知；駁回後 R 看到原因；填報追蹤正確標示未填／逾期。

**FR-4.2.3 R 回報完成（無後續）** — 角色：R
- 描述：任務已完成且無後續時，按「回報完成（無後續）」。
- 規則：任務移至「待確認」，期間不再催填；此為自我回報，正式完成仍由 A 確認；可於「待確認」取消回報。若該任務指派人設有 R主管，完成報告須先經 R主管核准，A 才會在待確認看到。
- 驗收：回報後任務進入待確認；經 R主管核准後列入 A 的待確認清單。

**FR-4.2.4 A 撰寫並送出正式週報（補充概念）** — 角色：A
- 描述：撰寫台採分頁：頁層「本週彙整｜填任務報告」；每個任務內再分「看 R 報告｜我的補充／我的報告」。
  - **有指派人**：看 R 報告（唯讀，進度依此）＋我的補充（提供脈絡、**不影響進度**）。
  - **無指派人・葉任務**：我的報告（進度依此），可標記完成。
  - **無指派人・父任務**：由子層聚合，僅顯示說明、不需填寫。
  - 任務清單清楚標示哪些有押人／未押人；待 A 填報的無押人任務以琥珀色標示。
- 規則：**送出**才發布於更新紀錄並通知全員、更新進度、套用標記完成；**暫存**僅保存內容，不發布、不更新進度。
- 驗收：送出後更新紀錄／進度更新、通知全員；A 對「有押人」任務的補充不改變該任務進度；暫存後重開內容仍在。

**FR-4.2.5 A 審核 R 的回報完成（確認 100%）** — 角色：A
- 描述：A 於審核中心對 R 已回報完成的任務「審核通過」或「駁回」。
- 規則：
  - **前置（gating）**：若該任務指派人設有 R主管，R 的完成報告須先經 R主管核准，A 才會在待確認看到；未設 R主管則直接進 A。
  - 審核通過 ＝ **確認任務 100% 完成**：設 100%、記錄完成日與完成人，反映於甘特（完成）、完成區與里程碑。（**本版新流程，取代舊「審核通過不改完成度」**。）
  - 駁回：填原因、清除回報，退回 R 的「待完成」。
- 驗收：通過後任務 100% 並入完成區、里程碑同步；未過 R主管前 A 看不到該任務；駁回後 R 看到原因並可重做。

### 4.3 進度與狀態

**FR-4.3.1 任務進度（依指派人）** — 規則
- 進度來源依任務是否有指派人分流：
  - **有指派人**：以該指派人（R，經 R主管核准後）的報告日期做時間推算；A 的補充不影響。
  - **無指派人・葉任務**：以 A 的報告日期推算（該任務報告本就由 A 寫）。
  - **無指派人・父任務**：由其子任務依天數加權聚合，A 不需另寫父層。
- 一律自動最高 99%；標記完成／A 確認 R 回報完成才 100%。
- 驗收：有押人任務進度只受該 R 報告影響、A 補充不動；無押人葉任務隨 A 報告推進；無押人父任務等於子層聚合。

**FR-4.3.2 里程碑進度** — 規則
- 里程碑進度＝其下所有「計入」任務依天數加權平均；為避免重複加權，**排除「無指派人的純聚合父任務」**（其值已由子任務貢獻）。所有計入任務完成才 100%。
- 驗收：任一任務未完成則里程碑 < 100%；聚合父任務不被重複計入。

**FR-4.3.3 任務狀態燈** — 規則
| 狀態 | 條件 |
|---|---|
| 待辦 | A 尚未發布進度 |
| 進行中 | A 已有進度（>0%） |
| 逾期未開始 | 已過截止日、仍無進度 |
| 受阻 | 前序（上游）未完成 |
| 完成 | A 已標記完成 |
- 驗收：狀態燈依上表判定；「逾期 N 天」以截止日與今日另計，與狀態燈獨立。

### 4.4 標記完成

**FR-4.4.1 標記完成** — 角色：A
- 描述：於撰寫台對任務「標記完成」，填實際完成日。
- 規則：標記後為「待送出」，須送出本週報告才生效（設 100%）；父、子任務皆可標記；暫存會保留待標記完成。**完成日不硬卡截止日**（可晚於計畫截止日），是否申請延期由 A 另行判斷。
- 驗收：送出後任務完成；完成日晚於截止日仍可標記；暫存後重開待標記完成仍在。
- 備註：標記完成／申請延期對話框將「前序未完成」「已逾期」等注意事項統一收於上方（琥珀底色）呈現，避免長專案版面過雜。

### 4.5 更新紀錄

**FR-4.5.1 更新紀錄** — 角色：全員可看
- 描述：依填報週分組，呈現已發布的內容。
- 規則：呈現「R主管核准的 R 報告」與「A 送出的報告」；未經核准／發布的紀錄不列示（舊資料相容以 2026-07-12 為界，見 §9）。完成事件列於對應報告週，並顯示實際完成日。
- 驗收：更新紀錄不含未核准的 R 原始紀錄；完成事件落在報告週。

### 4.6 延期申請與審核

**FR-4.6.1 提出延期申請** — 角色：A
- 描述：任務需調整**計畫時程**時，A 以常駐入口提出延期申請，填原因與新日期；系統計算受影響任務範圍。
- 規則：
  - 延期是否提出**由 A 判斷**：報告或完成日超過計畫截止日**不強制**、也不再跳出強制申請視窗；當 A 認為專案確實需要改計畫日期時才提出。
  - 送出後 S 收到通知，該申請進入審核中。
- 驗收：報告超截止日不強制觸發延期；A 主動送出後 S 待審清單出現該申請。

**FR-4.6.2 審核中時程鎖定** — 規則
- 有延期審核中時，該專案時程鎖定（里程碑／任務日期、拖曳皆不可改），僅「指派人」可調整，並顯示提示。
- 驗收：審核中編輯專案時程被鎖；審核完成後解除。

**FR-4.6.3 S 審核** — 角色：S
- 描述：於審核中心查看「延期影響」，核准或駁回。
- 規則：多位 S 需全部核准才生效；任一駁回則退回、時程不變；結果通知申請人。
- 驗收：全數核准生效連動；任一駁回退回。

**FR-4.6.4 核准後連動** — 規則
- 延期群組（被延任務＋父層鏈＋所屬里程碑）延長；下游（排序在後的任務與里程碑）依順序順延；被延任務的子孫、上游不變。甘特圖畫出延長段。
- 驗收：核准後群組延長、下游順延；其餘任務不受影響。

### 4.7 通知

**FR-4.7.1 通知機制** — 規則
| 通知 | 觸發 | 對象 | 類型 |
|---|---|---|---|
| 任務指派 | 建立／編輯指派任務 | 被指派者 | 即時 |
| 新增工作紀錄 | R 送出工作紀錄 | A（每天每專案最多 1 則） | 即時 |
| 待審核報告 | R 送出報告 | R主管（未設則 A） | 即時 |
| 報告已進更新紀錄 | R主管核准報告 | A | 即時 |
| 待審核完成 | R 回報完成經 R主管核准 | A | 即時 |
| 週報已送出 | A 送出本週報告 | 全體團隊 | 即時 |
| 延期申請 | 送出延期申請 | S | 即時 |
| 審核結果 | S 完成審核 | 申請人 | 即時 |
| 逾期提醒 | 里程碑逾期（每 7 天 1 則） | A | 排程·限已開案 |
| 審核逾期 | R主管超時未審（>3 天；彙總、3 天去重） | A | 排程·限已開案 |
| 週報催繳 | 本週應填未填 | 當事 R | 排程·限已開案 |
- 規則：即時通知約 10 秒內自動顯示、切回分頁即時更新；排程通知僅對已開案專案發送。
- 驗收：即時通知自動出現；排程通知不對草稿專案發送。

**FR-4.7.2 通知呈現** — 全員
- 側邊欄**收合時仍顯示**通知鈴鐺與未讀數（彈窗往右展開）。
- 鈴鐺彈窗依類型顯示未讀摘要、清單可捲動、點擊可跳專案。
- 「通知中心」提供搜尋、全部／未讀／已讀切換，及類型篩選（有未讀的類型做一鍵快捷分頁、其餘收於「更多類型」下拉），篩選區獨立成一個區塊。
- 驗收：收合狀態看得到未讀數；通知中心清單可捲動；類型篩選僅列出有資料者。

### 4.8 採購與投資報酬（P）

**FR-4.8.1 採購項目 / 資本支出** — 角色：P
- 描述：維護專案的採購項目（站別、供應商、設備、數量、採購類型、成本）與投資報酬（ROI）參數。
- 規則：屬 P 角色職責；供成本與回收評估。
- 驗收：可新增／編輯採購項目與 ROI 參數並正確計算回收期。

### 4.9 檢視與儀表板

**FR-4.9.1 甘特圖（工作項目）** — 全員可看
- 呈現任務長條、進度百分比、狀態燈、里程碑。實際條（Actual）依已發布報告繪製、結束於**最後一筆報告日期**（非今天）；無指派人的聚合父任務其實際條由子孫報告彙總，tooltip 顯示實際起訖日。

**FR-4.9.2 側邊欄徽章** — 個人
- 顯示「待審核」（S 的待審延期數）與「風險任務」數，取自即時資料。

**FR-4.9.3 里程碑階段總覽（專案概覽）** — 全員可看；顯示設定限 A／pm／admin
- 描述：專案頁上以里程碑為「階段」的時間軸總覽：階段條（依狀態上色）、年月軸、Plan 與 Actual 兩列；Actual 依 A 發布報告的**最後日期**繪製（無指派人的聚合父任務由子孫彙總）。可收合，收合狀態記於個人偏好。
- 規則：提供「顯示設定」（存於專案、全域一致；限 A／pm／admin 調整、其他人套用）：
  - **重疊階段**：分開（自動分層、互不遮擋）／合併（擠成一列）。
  - **時間軸寬度**：貼合（全部縮入畫面）／展開時間軸（固定月寬、顯示月份、可橫向捲動，適合長專案）。
  - **顯示階段**：勾選要顯示哪些里程碑。
- 驗收：長專案切「展開時間軸」可見各月份並能橫向捲動、短專案切換不縮水；顯示設定由 A／pm／admin 調整後其他檢視者一致套用。

## 5. 主要業務流程

1. **建立 → 開案**：PM 建立專案結構 → 指派（含各成員 R主管）→ 開案（定版）。
2. **每週循環**：R 填工作紀錄 → **R主管審核**（通過＝進更新紀錄／駁回＝退回 R）→ A 撰寫正式報告與補充、並確認 R 回報的 100% 完成 → 進度、更新紀錄、甘特更新。（進度來源依指派人；未設 R主管者 R 報告回退由 A 審。）
3. **時程調整**：報告可超截止日；A 判斷需改計畫時程時提延期 → 審核中鎖定 → S 核准（連動）／駁回（不變）。

> 對應示意圖見 flow-diagrams.html（角色、生命週期、每週報告、進度、狀態、延期、通知）與 flow-example.html（報告彙整範例）。

## 7. 非功能需求

- **權限**：角色化操作範圍（見 §3）。
- **通知即時性**：即時通知約 10 秒內；切回分頁即時更新。
- **一致性**：進度／里程碑聚合於各入口（專案、我的任務、甘特）計算一致。
- **相容性**：日期以 UTC 日曆日判定「今天」，逾期判定跨模組一致。

## 8. 現況說明與已知限制

- 進度來源依指派人：有押人以 R 報告（經 R主管核准）為準、無押人葉以 A 報告、無押人父由子層聚合；A 對有押人任務的補充不驅動進度。
- R 的工作紀錄經 R主管核准（未設回退 A）後才入更新紀錄與甘特；100% 完成一律由 A 確認。
- 報告日期可超過計畫截止日；是否延期由 A 判斷、經 S 核准才連動。日常時程調整不連動。
- R主管為「每位成員各自指定」的報告審核人（per-member），非全域角色；未設定則回退由 A 審核。
- 舊資料相容：客戶匯入的歷史紀錄（無 publishedAt）以 2026-07-12 為界照舊全顯示，界線之後才以核准／A 送出為準。
- 權限目前以前端角色控管為主；部分 mutation API 的伺服器端授權為後續強化項目。
