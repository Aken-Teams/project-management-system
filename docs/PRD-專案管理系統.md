## 1. 產品概述

### 1.1 目的
提供以「里程碑—任務」為核心的專案管理平台，讓團隊依角色分工，透過每週報告更新進度、以延期審核控管時程，並以通知維持協作。

### 1.2 目標使用者
專案經理（PM）、當責者（A）、執行者（R）、審核者（S）、採購（P）、主管與一般成員。

### 1.3 核心設計原則
1. **A 為主**：官方進度、更新紀錄、甘特圖一律以 A 送出的報告為準。
2. **手動為主**：日常時程以團隊手動調整為準，不自動連動。
3. **延期才連動**：僅「延期申請核准」會依規則連動群組與下游。

## 2. 名詞定義

| 名詞 | 定義 |
|---|---|
| 里程碑 | 專案的階段性節點，底下掛任務。 |
| 任務 / 子任務 | 工作項目，可多層巢狀（里程碑＋最多 5 層任務，共 6 層）。 |
| 工作紀錄 | R 每週填寫的工作內容（日期＋內容＋附件）。 |
| 週報 / 正式報告 | A 彙整後送出的報告，作為官方依據。 |
| 填報週（weekOf） | 報告所屬的週別（週一為基準）。 |
| 標記完成 | A 將任務設為完成（100%），需填實際完成日。 |
| 開案 | 專案由「草稿」進入「已開案」，時程定版。 |
| 延期申請 | 調整時程的正式申請，經 S 審核。 |

## 3. 角色與權限

### 3.1 系統角色（登入身分）
| 角色 | 權限範圍 |
|---|---|
| admin 管理員 | 系統設定、使用者與角色、通知與報告排程；最高權限。 |
| pm 專案經理 | 建立與管理專案、指派任務、開案、審核。 |
| executive 主管 | 跨專案儀表板、整體進度與風險。 |
| member 一般成員 | 填寫自身工作紀錄、檢視被指派任務。 |

### 3.2 專案分工角色（每專案指派，RASCI＋P）
| 角色 | 職責 |
|---|---|
| R 負責 | 執行任務、填寫工作紀錄、回報進度、管理子任務。 |
| A 當責 | 撰寫正式週報、審核 R 回報、標記任務完成、提出延期申請。 |
| S 審核 | 審核延期申請（核准／駁回）。 |
| P 採購 | 設備採購與供應商管理、採購項目與資本支出（投資報酬）維護。 |
| C 諮詢 | 決策前被徵詢的專家。 |
| I 知會 | 被告知進度與決策結果，不直接參與執行。 |

## 4. 功能需求

> 每項標示：**角色**（操作者）、**描述**、**規則**、**驗收標準**。

### 4.1 專案建立與開案

**FR-4.1.1 建立專案（精靈）** — 角色：PM／admin
- 描述：以精靈建立專案，分頁依序為：基本資訊、SMART 目標、專案定義、團隊與風險、時程里程碑。可「AI 快速產生規劃」帶入初稿，或手動輸入；可隨時「儲存草稿／載入草稿」。
- 規則：建立後狀態為「草稿」；被指派者收到「任務指派」通知；指派人僅能從專案成員中選擇。
- 驗收：完成精靈後專案出現於看板（草稿）；被指派者收到通知。

**FR-4.1.2 里程碑與任務結構編輯** — 角色：PM／admin
- 描述：於「時程里程碑」分頁建立里程碑與任務的階層。每列可填：名稱、日曆天、開始／結束日期、指派人、優先度。
- 規則：
  - 新增里程碑、任務、子任務。
  - 縮排／升階：任務可變為上一列的子項，或往上提一層（子任務→任務→里程碑）。
  - 拖曳：調整順序或改變層級（拖曳過程日期保留）。
  - 里程碑降階為相鄰里程碑下的任務。
  - 階層上限 6 層（里程碑＋5 層任務）。
  - 日期以手動輸入為準，不自動連動。
- 驗收：可建立 6 層結構；縮排／升階／拖曳操作正確且日期保留。

**FR-4.1.3 開案** — 角色：PM／admin
- 描述：規劃完成後點「開案」，狀態由「草稿」變「已開案」。
- 規則：開案後，計畫日期調整需經延期審核；系統開始發送逾期與週報催繳通知。草稿階段不催繳、不計逾期。
- 驗收：開案後日期調整觸發延期流程；排程通知僅對已開案專案發送。

### 4.2 每週報告

**FR-4.2.1 R 填寫工作紀錄** — 角色：R
- 描述：於「我的任務 › 填寫週報」選填報週別，填寫日期＋工作內容（可附件、多筆），提交。視窗含四分頁：待完成、待確認、完成區、審視歷程。
- 規則：提交後通知 A；此為原始紀錄，未經 A 發布前不影響官方進度與甘特圖。
- 驗收：提交後顯示「週報已提交」；A 收到「有新的工作紀錄」通知。

**FR-4.2.2 R 回報完成（無後續）** — 角色：R
- 描述：任務已完成且無後續時，按「回報完成（無後續）」。
- 規則：任務移至「待確認」等 A 審核，期間不再催填；此為自我回報，正式完成仍由 A 標記；可於「待確認」取消回報。
- 驗收：回報後任務進入待確認並列入 A 的待審核清單。

**FR-4.2.3 A 撰寫並送出正式週報** — 角色：A
- 描述：於撰寫台選週別、填彙整說明、挑任務撰寫報告（可查看／匯入 R 紀錄）、可標記完成、可暫存或送出。
- 規則：**送出**才會發布於更新紀錄並通知全員、更新進度、套用標記完成；**暫存**僅保存內容（含待標記完成），不發布、不更新進度。
- 驗收：送出後更新紀錄出現該報告、進度更新、通知全員；暫存後重開內容仍在且不誤報未儲存。

**FR-4.2.4 A 審核 R 的回報完成** — 角色：A
- 描述：A 於「我的任務」週報審核區，對 R 已回報的任務「審核通過」或「退回」。
- 規則：
  - 審核通過：認可 R 的報告並發布於更新紀錄；**不改變進度／完成度**；任務移至 R 的「完成區」。
  - 退回：附原因退回，任務回到 R 的「待完成」。
  - 「審核通過」與「標記完成（設 100%）」為不同動作；正式完成以標記完成為準。
- 驗收：審核通過後 R 回報發布於更新紀錄；退回後 R 看到原因並可重做。

### 4.3 進度與狀態

**FR-4.3.1 任務進度** — 規則
- 每個任務（含父、子）進度依其 A 報告日期做時間推算，自動最高 99%；標記完成才 100%。父／子任務各自計算，互不聚合。
- 驗收：進度隨報告日期推進；未標記完成不超過 99%。

**FR-4.3.2 里程碑進度** — 規則
- 里程碑進度＝其下所有層級任務依天數加權平均；所有任務完成才 100%。
- 驗收：任一任務未完成則里程碑 < 100%。

**FR-4.3.3 任務狀態燈** — 規則
| 狀態 | 條件 |
|---|---|
| 待辦 | A 尚未發布進度 |
| 進行中 | A 已有進度（>0%） |
| 逾期未開始 | 已過截止日、仍無進度 |
| 受阻 | 前序（上游）未完成 |
| 完成 | A 已標記完成 |
- 驗收：狀態燈依上表判定；「逾期 N 天」以截止日與今日另計，與狀態燈獨立。

### 4.4 標記完成

**FR-4.4.1 標記完成** — 角色：A
- 描述：於撰寫台對任務「標記完成」，填實際完成日。
- 規則：標記後為「待送出」，須送出本週報告才生效（設 100%）；父、子任務皆可標記；暫存會保留待標記完成；實際完成日超過截止日時，系統建議先申請延期。
- 驗收：送出後任務完成；暫存後重開待標記完成仍在。

### 4.5 更新紀錄

**FR-4.5.1 更新紀錄** — 角色：全員可看
- 描述：依填報週分組，呈現經 A 發布的內容。
- 規則：呈現 A 送出的報告，及 A 審核通過的 R 回報；未經 A 發布的紀錄不列示。完成事件列於 A 送報告的那一週，並顯示實際完成日。
- 驗收：更新紀錄不含未發布的 R 原始紀錄；完成事件落在報告週。

### 4.6 延期申請與審核

**FR-4.6.1 提出延期申請** — 角色：A
- 描述：任務需調整時程時，A 於撰寫台提出延期申請，填原因與新日期；系統計算受影響任務範圍。
- 規則：送出後 S 收到通知，該申請進入審核中。
- 驗收：送出後 S 待審清單出現該申請。

**FR-4.6.2 審核中時程鎖定** — 規則
- 有延期審核中時，該專案時程鎖定（里程碑／任務日期、拖曳皆不可改），僅「指派人」可調整，並顯示提示。
- 驗收：審核中編輯專案時程被鎖；審核完成後解除。

**FR-4.6.3 S 審核** — 角色：S
- 描述：於審核中心查看「延期影響」，核准或駁回。
- 規則：多位 S 需全部核准才生效；任一駁回則退回、時程不變；結果通知申請人。
- 驗收：全數核准生效連動；任一駁回退回。

**FR-4.6.4 核准後連動** — 規則
- 延期群組（被延任務＋父層鏈＋所屬里程碑）延長；下游（排序在後的任務與里程碑）依順序順延；被延任務的子孫、上游不變。甘特圖畫出延長段。
- 驗收：核准後群組延長、下游順延；其餘任務不受影響。

### 4.7 通知

**FR-4.7.1 通知機制** — 規則
| 通知 | 觸發 | 對象 | 類型 |
|---|---|---|---|
| 任務指派 | 建立／編輯指派任務 | 被指派者 | 即時 |
| 新增工作紀錄 | R 送出工作紀錄 | A（每天每專案最多 1 則） | 即時 |
| 週報已送出 | A 送出本週報告 | 全體團隊 | 即時 |
| 延期申請 | 送出延期申請 | S | 即時 |
| 審核結果 | S 完成審核 | 申請人 | 即時 |
| 逾期提醒 | 里程碑逾期（每 7 天 1 則） | A | 排程·限已開案 |
| 週報催繳 | 本週應填未填 | 當事 R | 排程·限已開案 |
- 規則：即時通知約 10 秒內自動顯示、切回分頁即時更新；排程通知僅對已開案專案發送。
- 驗收：即時通知自動出現；排程通知不對草稿專案發送。

### 4.8 採購與投資報酬（P）

**FR-4.8.1 採購項目 / 資本支出** — 角色：P
- 描述：維護專案的採購項目（站別、供應商、設備、數量、採購類型、成本）與投資報酬（ROI）參數。
- 規則：屬 P 角色職責；供成本與回收評估。
- 驗收：可新增／編輯採購項目與 ROI 參數並正確計算回收期。

### 4.9 檢視與儀表板

**FR-4.9.1 甘特圖（工作項目）** — 全員可看
- 呈現任務長條、進度百分比、狀態燈、里程碑；實際條依 A 發布的報告日期繪製。

**FR-4.9.2 側邊欄徽章** — 個人
- 顯示「待審核」（S 的待審延期數）與「風險任務」數，取自即時資料。

## 5. 主要業務流程

1. **建立 → 開案**：PM 建立專案結構 → 指派 → 開案（定版）。
2. **每週循環**：R 填工作紀錄 → A 審核 R 回報／撰寫正式報告 → 送出 → 進度、更新紀錄、甘特更新。
3. **時程調整**：A 提延期 → 審核中鎖定 → S 核准（連動）／駁回（不變）。

## 7. 非功能需求

- **權限**：角色化操作範圍（見 §3）。
- **通知即時性**：即時通知約 10 秒內；切回分頁即時更新。
- **一致性**：進度／里程碑聚合於各入口（專案、我的任務、甘特）計算一致。
- **相容性**：日期以 UTC 日曆日判定「今天」，逾期判定跨模組一致。

## 8. 待決議設計議題（需求方確認）

| # | 議題 | 現況 | 可選方案 |
|---|---|---|---|
| 1 | 父任務起訖日是否須與子任務一致 | 各自獨立 | 父自動＝子的最早～最晚範圍 |
| 2 | 父任務報告是否須與子任務相符 | 各自撰寫 | 檢核父報告日期不早於最新子報告 |
| 3 | 父任務百分比是否改以子層聚合 | 父看自己 | 父＝子任務加權平均 |
| 4 | 延期駁回後、已逾期任務處理 | 未明確 | 重送延期／原截止日內補完／其他 |
| 5 | 延期逾一週未審是否暫停 A 週報 | 不暫停 | 暫停直到 S 審核完成 |

> 詳細對照示意圖見 flow-issues.html。

## 9. 現況說明與已知限制

- 官方進度、更新紀錄、甘特圖以 A 送出的報告為準；R 原始紀錄未經 A 發布不單獨呈現。
- 日常時程調整不連動；僅延期核准連動。
- 延期申請目前僅由 A 提出。
- 權限目前為前端角色控管；伺服器端授權為後續強化項目（不在本次範圍）。
